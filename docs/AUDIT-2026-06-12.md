# Audyt nexo-sfera-api — 2026-06-12

Audyt na bazie SDK **nexo 60.1.1.9292** (`docs/nexoSDK_60.1.1.9292/`). Szczegółowe raporty robocze:
`scratchpad/audit/{sdk-capabilities,api-surface,infrastructure,docs-hygiene,coverage-gaps}.md`.

## Stan projektu (TL;DR)

- 61 kontrolerów, ~42k LOC w kontrolerach, **354 endpointy**, 97 użytych managerów SDK.
- Pokrycie możliwości Sfery: **~22–25%** (z ~273 obiektów biznesowych CRUD w SDK API ekspozycja ~85 do odczytu, ~40 z zapisem). Mapa luk + roadmapa 8 faz: `scratchpad/audit/coverage-gaps.md`.
- SDK 60.1.0→60.1.1: **zero zmian API** (jest zgodność); 60.0.1→60.1.0: 3 nowe typy (KSeF zakupy zagraniczne, auto-wiązanie e-faktur, błąd e-ZLA), KEDU 5.7, breaking change w kliencie HTTP Sello.

## Naprawione w tym audycie (2026-06-12)

| # | Problem | Naprawa |
|---|---------|---------|
| 1 | **KRYTYCZNE**: `/mcp` bez autoryzacji — narzędzia zapisu (faktury, paragony, kontrahenci) dostępne bez klucza | `app.MapMcp("/mcp").RequireAuthorization()` (Program.cs) |
| 2 | **KRYTYCZNE**: 10 endpointów `DocumentsController` (w tym `GET /api/documents`, korekty, faktura zaliczkowa/marża, powiązania) dotykało SDK poza wątkiem STA | Wszystkie owinięte w `ExecuteWithLockAsync` |
| 3 | 8 endpointów `debug/*` w `CustomersController` + 4 w `DiagnosticsController` bez locka | Owinięte w `ExecuteWithLockAsync` |
| 4 | Rekonekcja martwa: `InitializeAsync` robił early-return przy `_sfera != null`, a `SettingsController.Reconnect` **disposował singleton** (trwale ubijał kolejkę pracy) | Nowe `ReinitializeAsync()` — dispose starego uchwytu + reconnect w całości na wątku STA; oba endpointy reconnect przepięte |
| 5 | Po nieudanym `SwitchOperatorIfNeeded` przywracano poprzedniego operatora **złym hasłem** (zawsze hasłem z settings) | Śledzenie hasła bieżącego operatora + fallback na operatora domyślnego |
| 6 | Async-wariant `ExecuteWithLockAsync` blokował STA przez `GetResult()` bez pompowania komunikatów (deadlock przy kontynuacjach WinForms sync-context) | Pompowanie `Application.DoEvents()` podczas oczekiwania |
| 7 | Po nieudanym logowaniu operatora `_sfera` zostawał ustawiony (`IsConnected == true` mimo braku zalogowania) | Sprzątanie pół-zainicjalizowanego uchwytu w `ConnectCore()` |

## Otwarte problemy — wysoki priorytet

1. **Multi-firma jest fikcją konfiguracyjną**: per-klucz `Database`/`DefaultWarehouse`/`DefaultBranch` trafiają do claims, ale **nikt ich nie konsumuje** — wszystkie klucze pracują na jednej bazie z `Sfera:*`. Per-klucz działa tylko operator (`NexoLogin`/`NexoPassword`), i to wyłącznie w 2/61 kontrolerów (`Documents`, `WarehouseDocuments`) — operator "przecieka" między klientami w pozostałych 59. Do decyzji architektonicznej: pula połączeń per baza vs. jawny parametr firmy.
2. **Sekrety w repo**: `src/appsettings.json` jest śledzony i zawiera realnie wyglądający klucz API + dane logowania nexo; `.claude/settings.local.json` zawiera produkcyjny token (nieśledzony, ale do rotacji).
3. **232 puste bloki `catch {}`** połykają błędy SDK (Documents 35, ProductTemplates 30, Assembly 28) — debugowanie produkcji na ślepo.
4. **God-kontrolery**: Documents 6 977 LOC, Diagnostics 3 249, WarehouseDocuments 2 807; 101 DTO zdefiniowanych inline w kontrolerach; mapowania `MapToDto` powielone w ~8 kontrolerach; paginacja `Skip/Take` kopiowana w 45.
5. **Wydajność**: 381 pełnych skanów (`Wszystkie()`/`SafeGetAll`) z paginacją in-memory, wszystko zserializowane na jednym wątku STA → sufit przepustowości całego API. `GetExtensionManager` skanuje wszystkie assembly przy każdym wywołaniu (do cache'owania).
6. **Niespójna koperta odpowiedzi**: `ApiResponse<T>` vs surowe obiekty (Dictionary/JPK/Warehouses) vs HTTP 200 z polem `.Error` (Ksef) — Laravel-klient potrzebuje jednego formatu. Ujednolicenie = breaking change, do decyzji.
7. **600+ ręcznych try/catch → `StatusCode(500)`** mimo istniejącego `ErrorHandlingMiddleware` — do scentralizowania.
8. **Endpointy debug/diagnostyczne** (11×`debug/*` + cały `DiagnosticsController`, w tym mutujący POST) bez bramkowania środowiskiem.
9. **CORS AllowAll + auth `?api_key=` w query stringu** (klucz ląduje w logach proxy) + Swagger anonimowy w produkcji + `ex.Message` w odpowiedziach 500.
10. **Polskie identyfikatory** w kodzie (np. `TestPodmioty`, `GetAddressSzczegoly`, `TestZnajdz` w CustomersController, segmenty tras `/montaz`) — niezgodne ze standardem projektu (identyfikatory EN).

## Higiena repo

- Pack gita **783 MiB**; DLL-e SDK commitowane **podwójnie** (`lib/nexo-sdk` 762 plików + `src/lib/nexo-sdk` 937 plików) — kwestia także licencyjna.
- Kandydaci do usunięcia: `FIXES_SUMMARY.md`, `IMPLEMENTATION_SUMMARY.md`, `RECEIPT_FIX_SUMMARY.md`, `SERVICE_VALIDATION_FIX.md` (logi robocze tej samej paczki fixów ze stycznia), `API-COMPLETION-PLAN.md` (wykonany, zamrożony na "18 kontrolerów"), `sdk-structure.md` (87k linii JSON-dump), martwy `JwtSettings` + pakiety `JwtBearer`/`AspNetCore.OpenApi`, katalogi-widma `src/src/`, puste `src/scripts/`, `.idea/` w repo.
- README pokrywa <1/3 API, odwołuje się do usuniętego `nexoSDK_58.0.2.8985/`; brak sekcji o kopercie odpowiedzi, błędach, paginacji i limitach współbieżności (jeden wątek STA!) — czyli wszystkiego, czego potrzebuje integrator Laravel.
